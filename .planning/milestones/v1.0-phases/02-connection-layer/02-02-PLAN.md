<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Timer callback -> manager state | Delayed retry callbacks can fire after user/manual actions or disposal. |
| Network failure -> status payload | Failure reasons from fetch/HTTP enter status events consumed by later UI. |
| Stored connection metadata -> repeated network attempts | Workspace URL controls repeated outbound probes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-T | Tampering | Retry state after concurrent probes | mitigate | Use attempt/generation checks so stale completions cannot overwrite newer status. |
| T-02-02-I | Information Disclosure | Error/status events | mitigate | Preserve Plan 01 safe error handling; never include raw bearer tokens in emitted errors. |
| T-02-02-D | Denial of Service | Failed endpoint retry loop | mitigate | Exponential backoff starts at 2_000 ms and caps at 60_000 ms; manual retry clears existing timer before probing. |
| T-02-02-D2 | Denial of Service | Disposed workspace timers | mitigate | `dispose(workspaceId)` clears timers and late async completions cannot schedule new timers. |
| T-02-02-E | Elevation of Privilege | Renderer/preload/IPC surface | mitigate | No renderer, preload, IPC, or BrowserWindow broadcast additions in this plan. |
| T-02-SC | Tampering | npm installs | accept | No package-manager install tasks in this plan. |
</threat_model>
