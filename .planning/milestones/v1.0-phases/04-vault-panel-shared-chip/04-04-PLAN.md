<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer -> preload | Vault panel sends list/retry/context-menu requests through `window.electronAPI` |
| FlashQuery vault data -> renderer | Entry names, titles, paths, status errors, and host text are untrusted display data |
| vault URI -> editor creation | User row actions create editor panels with `flashquery://` URIs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04-01 | Elevation of Privilege | `FlashQueryVaultPanel` renderer IPC | mitigate | Use only typed preload APIs; no Electron, Node, filesystem IPC, MCP client, or main-process imports. |
| T-04-04-02 | Tampering | vault row context menu | mitigate | Document rows expose exactly Open/Open on Canvas; folder rows do not call `showContextMenu`; no create/rename/delete/move/copy affordances. |
| T-04-04-03 | Information Disclosure | status error/host display | mitigate | Display only configured URL host and status error from existing sanitized broadcast; never read or render bearer token. |
| T-04-04-04 | Spoofing | editor URI creation | mitigate | Use canonical shared `buildVaultUri(workspaceId, entry.vaultPath)` helper from `src/shared/flashqueryUri.ts`, not manual string concatenation or main-process imports. |
| T-04-04-05 | Denial of Service | async list/refresh races | mitigate | Use in-flight guards and stale-response suppression so old list responses do not corrupt current tree state. |
| T-04-04-SC | Tampering | npm installs | accept | This plan performs no package-manager installs. |
</threat_model>
