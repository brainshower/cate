<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer connection payload -> workspace store | User-entered URL and token-bearing connection crosses into persistent metadata/token storage. |
| Manager status -> all renderer windows | Network error text and connection state become UI-observable. |
| Workspace mutation -> manager lifecycle | Config changes must invalidate stale client/retry state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-S | Spoofing | Connection URL | mitigate | Accept only parseable `http:` or `https:` URLs in v1. |
| T-03-02-T | Tampering | Workspace metadata | mitigate | Persist through `updateWorkspace` so existing validation/sanitization applies. |
| T-03-02-I | Information Disclosure | Bearer token | mitigate | Token storage stays in workspace manager/credentials helpers; tests assert no raw token in broadcasts/results. |
| T-03-02-D | Denial of Service | Stale retry timers | mitigate | Dispose manager state on set/clear/replacement before new connection behavior. |
| T-03-02-E | Elevation of Privilege | Generic renderer tool access | mitigate | Handler exposes only setConnection and status, no generic MCP calls. |
| T-03-SC | Tampering | npm installs | accept | No dependency installation in this plan. |
</threat_model>
