<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process->Electron app | E2E fixtures can influence runtime through env vars and must be scoped to test mode only. |
| renderer->main IPC | UI actions cross the preload bridge into privileged FlashQuery IPC handlers. |
| main->stub HTTP MCP | Main process sends public info probes and authenticated MCP tool calls to a local test server. |
| test stub state->assertions | Mutable stub state can create false positives if not reset between tests. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-E | Elevation of Privilege | `CATE_E2E_USER_DATA_DIR` | mitigate | Read the override only inside `CATE_E2E=1`; preserve production userData behavior. |
| T-07-02-I | Information Disclosure | E2E logs and persisted state | mitigate | Do not log bearer token values; use fixed test tokens only and assert redaction where failures include token-like strings. |
| T-07-02-T | Tampering | FlashQuery stub state | mitigate | Provide `resetCounts()` and document reset helpers; call them in spec setup/teardown to prevent stale-state false positives. |
| T-07-02-R | Repudiation | E2E test evidence | mitigate | Name tests with T-E IDs and assert visible UI plus stub counters/state so summaries can cite exact proof. |
| T-07-02-E2 | Elevation of Privilege | renderer FlashQuery access | mitigate | Specs must drive UI/preload IPC; no renderer-side Node/Electron direct access or production MCP client import. |
| T-07-02-SC | Tampering | npm installs | accept | No package installs are planned. |
</threat_model>
