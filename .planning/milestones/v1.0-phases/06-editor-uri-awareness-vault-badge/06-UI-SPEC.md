## Visual Contract

| Element | Contract |
|---------|----------|
| Badge trigger | Render only when `parseVaultUri(filePath)` returns a non-null value for the editor panel's `filePath`. |
| Local-file regression | Local files and scratch editors render no badge and their title chrome remains visually unchanged. |
| Badge placement | Title chrome, after the dirty-state/title area and before right-side actions. Existing visible title chrome may live outside `EditorPanel`; implement at the actual chrome layer that owns the visible title for docked tabs, canvas-hosted tabs, and detached panel windows, or pass a badge slot from `EditorPanel` only if that preserves those surfaces. |
| Badge surface | Reuse the shared chip surface from `src/renderer/components/Chip.tsx` or a directly factored primitive in that file. Surface values: 20-22px height, pill radius 999, `rgba(255,255,255,0.04)` background, `1px solid rgba(255,255,255,0.06)` border, 11px system font. Do not duplicate these styles in `EditorPanel.tsx`. |
| Badge icon | Phosphor `Vault`, 12px, color `#5AD8B8`, `aria-hidden="true"`. |
| Badge copy | Exact visible composition: `Vault . <host>`. Host is parsed from the workspace FlashQuery connection URL. Do not use alternate separators in Phase 6. |
| Host fallback | If the workspace connection URL is unavailable or unparsable, show `Vault` without a misleading host. Do not show raw `flashquery://` URI text in the badge. |
| Tooltip | On hover/focus after 500ms or Cate's existing tooltip delay, show a tooltip with the full decoded `vaultPath` returned by `parseVaultUri(filePath)`. Tooltip surface uses the existing chip tooltip pattern: rounded-md, `border-subtle`, `bg-surface-4`, compact `px-2 py-1`, `text-secondary`/`text-muted`, `shadow-2xl`. |
| Dirty indicator | Dirty marker behavior stays identical to local editors. The badge does not replace, recolor, or add a second dirty indicator. |
| Status bar | No new vault status bar is added. Explicitly do not implement `Vault . rev 42`, `Vault - rev 42`, `Vault · rev 42`, revision chips, version tokens, or conflict indicators. |

The badge should read as a quiet source marker, not a call to action. It must not dominate the title or reduce the usability of close, drag, dock, split, maximize, or node controls.

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Click | Badge is inert in v1. It must not open the vault panel, retry a connection, save, reveal in tree, or navigate. |
| Hover | Shows the decoded vault-relative path tooltip. Tooltip must not require a click. |
| Focus | If the badge can receive focus because of implementation mechanics, focus shows the same tooltip. Prefer a non-focusable inert element when practical. |
| Keyboard | No new keyboard shortcut. Existing editor shortcuts, including save and close-confirm flows, remain unchanged. |
| Drag/title chrome | Badge must not interfere with title-bar dragging or tab dragging. If placed in an Electron draggable region, mark the badge area as `no-drag` only if needed for tooltip behavior and do not create accidental click targets. |
| Save/disconnected | The badge does not reflect connection state. Vault saves still attempt IPC even when disconnected; save failure UI belongs to editor save handling, not the badge. |
| Side-by-side editors | A local editor and a vault editor can appear on the same canvas; the only visual difference is the vault badge on the vault editor. |

## Accessibility And Keyboard Notes

| Concern | Contract |
|---------|----------|
| Accessible name | Badge accessible label: `Vault document from <host>` when host is known, otherwise `Vault document`. |
| Tooltip relationship | Tooltip uses `role="tooltip"` and is connected with `aria-describedby` if the badge is focusable. |
| Icon semantics | Vault icon is decorative because the text label provides meaning. |
| Contrast | `Vault` label uses `text-primary` or equivalent brighter text; host uses `text-muted` or equivalent muted text; icon uses `#5AD8B8`. |
| Keyboard trap | No focus trap, popover, or modal behavior. Tooltip disappears on blur, Escape, or mouse leave if implemented with state. |
| Motion | No animation required. Do not add spinner/status animation to the vault badge. |

## Component Ownership And Code Refs

| File | Ownership |
|------|-----------|
| `src/renderer/components/Chip.tsx` | Source of truth for chip/badge surface. Extend with a custom-content mode or extract a shared surface primitive here. |
| `src/renderer/panels/EditorPanel.tsx` | Owns vault URI detection for read/save/diff behavior and can compute badge metadata if the implementation routes it through panel state/chrome. It must not duplicate chip styling. |
| `src/renderer/docking/DockTabBar.tsx` | Existing visible dock tab title chrome. Badge placement may need to land here for docked editor tabs. |
| `src/renderer/docking/DockTabStack.tsx` | Pass-through boundary if badge metadata must reach tab rendering. |
| `src/renderer/canvas/CanvasNode.tsx` | Canvas-hosted tab stack and right-side controls. Verify badge does not collide with lock/maximize/close controls. |
| `src/renderer/shells/PanelWindowShell.tsx` | Detached panel title chrome. If detached editor windows show titles, vault badge must be considered here or explicitly documented as not visible in detached shell for Phase 6. |
| `src/shared/flashqueryUri.ts` | Use `parseVaultUri(filePath)` for the badge trigger and tooltip path. Do not parse URIs ad hoc. |
| `src/renderer/stores/appStore.ts` and `src/shared/types.ts` | Workspace connection URL and `PanelState.filePath` source for host/path metadata. |

Implementation decision required before coding: because visible title chrome is not wholly owned by `EditorPanel.tsx`, choose a single badge metadata path that covers the title surfaces Phase 6 intends to support. The preferred contract is a small reusable `VaultBadge`/chip-content component plus chrome-level rendering from panel `filePath` and workspace connection data.

## Out Of Scope And Drift Blocks

The following must not be implemented in Phase 6 UI:

| Item | Reason |
|------|--------|
| `Vault . rev 42`, `Vault - rev 42`, `Vault · rev 42`, revision chips, version badges | Product UI Spec marks this as design-spec drift; v1 has no revision display. |
| Conflict/staleness badges or `expected_version` UI | REQ-042 keeps v1 last-write-wins and conflict detection deferred. |
| Frontmatter, title, tag, YAML, or metadata editor UI | REQ-041 keeps v1 body-only in the editor. |
| Vault panel reveal/open-on-click from the badge | Badge is not clickable in v1. |
| New panels, dialogs, E2E flows, revision status bars, status bars, or conflict/frontmatter UI | Outside this phase scope. |
| Local-file title redesign | T-I-096 requires no-badge regression for local editors. |
| shadcn/Radix initialization | Cate already has a manual token/component system and this phase only extends existing chrome. |
