<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| renderer-to-preload | Renderer may request graph metadata but cannot access Electron, Node, or FlashQuery credentials directly. |
| preload-to-main IPC | `flashquery:queryGraph` parameters cross from untrusted renderer into privileged main. |
| main-to-FlashQuery | Main calls MCP `query_graph` with stored credentials and returns only normalized graph data. |
| graph-payload-to-provider | Node metadata may be partial, malformed, or unavailable per chunk. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-27-05 | Elevation of Privilege | `window.electronAPI.flashqueryQueryGraph()` | mitigate | Expose only typed `flashqueryQueryGraph()` rather than a generic MCP bridge; renderer receives no credentials. |
| T-27-06 | Tampering | `src/main/ipc/flashquery.ts` query_graph validation | mitigate | Validate `action`, `chunk_id`, `direction`, `include_content`, and `limit`; reject invalid shapes before `FlashQueryClientManager.queryGraph()`. |
| T-27-07 | Information Disclosure | query_graph bulk actions | mitigate | Preserve `include_content` gating so bulk actions do not shuttle nested node content unless requested; prove with `T-I-009`. |
| T-27-08 | Denial of Service | provider node metadata backfill | mitigate | Use per-chunk degradation and diagnostics so one malformed/failed node result cannot blank the panel; prove with `T-U-015` and `T-U-025`. |
| T-27-09 | Information Disclosure | diagnostics/test fixtures | mitigate | Keep token redaction invariant from Wave 1 for query_graph errors; no fixture should contain bearer tokens or connection credentials. |
| T-27-SC | Tampering | npm installs | accept | No new packages are installed; use existing Electron, React, Zustand, and Vitest stack. |
</threat_model>
