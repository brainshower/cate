<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| renderer-to-preload-to-main | Renderer graph options are untrusted and must be validated before FlashQuery calls. |
| main-to-FlashQuery | Main owns bearer tokens and connection credentials; renderer must never receive them. |
| FlashQuery-to-renderer data | Graph payloads may be partial or malformed and must not crash renderer validation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-27-01 | Information Disclosure | `FlashQueryClientManager` diagnostics | mitigate | Redact bearer tokens, URLs with credentials, and connection secrets in graph normalization errors; prove with `T-U-028`. |
| T-27-02 | Tampering | `src/main/ipc/flashquery.ts` document connection options | mitigate | Validate include and graph option shapes before calling FlashQuery; reject invalid graph limits and invalid include entries with `T-I-004`. |
| T-27-03 | Denial of Service | `src/renderer/lib/semanticConnections.ts` runtime/result validation | mitigate | Optional/malformed graph fields become omissions or diagnostics; null `score` does not invalidate useful rows; prove with `T-U-003` and `T-U-026`. |
| T-27-04 | Elevation of Privilege | Renderer graph access | mitigate | This plan does not expose direct FlashQuery credentials or generic tool calls; renderer remains limited to typed preload APIs in later plan. |
| T-27-SC | Tampering | npm installs | accept | No new packages are installed; existing package-lock dependencies remain unchanged. |
</threat_model>
