# Plan 17.2: Registry Discovery And Eligible Tool Registration

<objective>
Implement FlashQuery registry discovery, schema translation, eligible Pi tool registration, and no-provider guarantees for native and brokered FlashQuery MCP tools.
</objective>

<threat_model>
## Threat Model

- **High:** Registering non-current or non-host-eligible tools could expose unsafe host actions to Pi. Mitigation: centralize filtering and test deprecated, unavailable, missing-metadata, and false-hostEligible cases.
- **High:** Registering FlashQuery as a Pi provider would route host chat completion through the wrong auth/control plane. Mitigation: no calls to `pi.registerProvider`; add a mock assertion and ProvidersView absence check.
- **Medium:** Incorrect schema translation could let invalid tool args reach FlashQuery or make eligible tools unusable. Mitigation: cover object, string, number, boolean, array, enum, optional, and unknown schema fallback cases.
- **Medium:** Brokered MCP tools may collide by name with native tools. Mitigation: normalize names deterministically and test collision behavior.
</threat_model>
