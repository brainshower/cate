# Plan 17.3: Workspace Lifecycle, Stale Tools, And Evidence

<objective>
Complete workspace-aware lifecycle handling for the FlashQuery Pi extension and produce the automated/manual evidence required for Phase 17 closeout.
</objective>

<threat_model>
## Threat Model

- **High:** A stale tool from workspace A could execute against workspace B after a switch. Mitigation: atomically swap current-client references, reconcile advertised/available tools, and test old/new registry behavior.
- **High:** Cancelling in-flight old-workspace calls could corrupt Pi tool execution state. Mitigation: retain the old client for started calls and close it only after the call settles or a safe timeout.
- **Medium:** A late registry refresh could overwrite a newer workspace's tool set. Mitigation: generation IDs/last-refresh-wins logic.
- **Medium:** E2E mocking of Pi extension discovery may be brittle. Mitigation: keep E2E focused on install/startup availability and record manual real-integration evidence for live provider behavior.
</threat_model>
