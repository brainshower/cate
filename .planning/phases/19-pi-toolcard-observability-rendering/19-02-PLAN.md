<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mocked Pi event -> Electron renderer DOM | Test-injected diagnostics cross into user-visible ToolCard rendering. |
| Manual real integration -> UAT evidence | Live FlashQuery/provider diagnostics may contain sensitive operational fields if recorded carelessly. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-02-I | Information Disclosure | `e2e/flashquery-pi-diagnostics.spec.ts` and `19-UAT.md` | mitigate | Include secret-like sentinel fields in mocked diagnostics and assert they are absent from visible DOM; redact or omit tokens, headers, handoff payloads, endpoint fields, request-init fields, cookies, provider keys, and bearer values from UAT evidence. |
| T-19-02-T | Tampering | Mock diagnostics fixtures | mitigate | Feed events through `window.__cateE2E.dispatchAgentEvent()` so E2E exercises the real `agentStore` event path and not a custom DOM shortcut. |
| T-19-02-R | Repudiation | Manual evidence | mitigate | Record exact command names, pass/blocker status, and manual prerequisite status in `19-UAT.md`; do not mark unavailable live integration as passed. |
| T-19-02-S | Spoofing | Server-side FlashQuery tool-loop E2E rendering | mitigate | Assert server-loop diagnostics appear only inside expanded `call_model` ToolCard content and not as free-standing chat-thread messages. |
| T-19-02-SC | Tampering | npm installs | accept | No package installs are planned; existing Playwright/Electron E2E stack is used. |
</threat_model>
