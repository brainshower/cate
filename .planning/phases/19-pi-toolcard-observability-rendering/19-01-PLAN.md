<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pi tool details -> renderer ToolCard | Untrusted structured diagnostics from FlashQuery/Pi are displayed in user-visible React UI. |
| Renderer diagnostics display -> session evidence | ToolCard text may become screenshots, E2E evidence, or manual evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01-I | Information Disclosure | `ChatThread.tsx` FlashQuery diagnostic rendering | mitigate | Render only whitelisted diagnostic fields and omit tokens, headers, bearer/auth values, cookies, handoff payloads, endpoint fields, request-init fields, and unknown objects. Keep renderer using sanitized `ToolMessage.flashquery` from Phase 18 only. |
| T-19-01-T | Tampering | `ToolMessage.flashquery` optional unknown data | mitigate | Use type guards for strings/numbers/arrays and omit malformed fields; never trust diagnostic object shape for control flow beyond `msg.name === 'call_model' || msg.name === 'call_macro'`. |
| T-19-01-S | Spoofing | Server-side FlashQuery tool-loop display | mitigate | Render server-side tool loop only inside expanded `call_model` ToolCard with clear FlashQuery sub-block styling; never create free-standing chat rows that imply Cate/Pi directly invoked those tools. |
| T-19-01-D | Denial of Service | Long messages payloads | mitigate | Put message payloads behind nested disclosure with bounded scroll, reusing existing `CodePreview`/bounded `<pre>` patterns. |
| T-19-01-SC | Tampering | npm installs | accept | No package installs are planned; existing React/Vitest/Testing Library stack is used. |
</threat_model>
