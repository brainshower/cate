## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pi host model to macro tool | Model-generated macro source or source_ref enters execution path. |
| Macro tool to user confirmation UI | Inline source crosses from model proposal to user-approved action. |
| FlashQuery MCP progress to renderer | Runtime progress becomes visible as partial tool output. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-07 | Elevation of Privilege | `macro-tool.ts` inline `source` | mitigate | Require `ctx.ui.confirm` before dispatching inline macro source; declined confirmation must not call FlashQuery. |
| T-18-08 | Tampering | `macro-tool.ts` `source_ref` | mitigate | Execute `source_ref` as a reference without rewriting it into inline source or bypassing workspace-scoped client generation checks. |
| T-18-09 | Spoofing | `macro-tool.ts` progress | mitigate | Use MCP request-scoped progress callback and forward only matching real progress notifications. |
| T-18-10 | Repudiation | `diagnostics.ts` macro result | mitigate | Preserve final result envelope trace array and needs_user_input details for later ToolCard audit. |
| T-18-11 | Information Disclosure | `macro-tool.ts` details | mitigate | Do not copy bearer tokens, handoff files, env vars, or transport headers into progress/details/session output. |
| T-18-12 | Spoofing | `macro-tool.ts` progress text | mitigate | Do not fabricate checkmarks, completion counts, elapsed times, or per-step rows; live text is latest real progress only. |
| T-18-SC | Tampering | npm installs | accept | No package-manager installs are planned in this plan. |
</threat_model>
