<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pi host model to FlashQuery extension | Tool params are untrusted model-generated inputs. |
| FlashQuery extension to FlashQuery MCP | Workspace credentials and refs cross into the MCP endpoint. |
| FlashQuery extension to renderer tool events | Diagnostics and system/error messages become user-visible session data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Information Disclosure | `client.ts` / `model-tool.ts` | mitigate | Do not include bearer tokens in `FlashQueryToolDetails`, result text, trace metadata, or tests; credentials stay in the MCP transport headers only. |
| T-18-02 | Tampering | `refs.ts` | mitigate | Preflight unresolved refs and block dispatch with exact message before `call_model` sees unresolved `{{ref:path}}`; preserve original ref path in diagnostics only. |
| T-18-03 | Spoofing | `trace.ts` | mitigate | Generate trace IDs inside the extension using workspace hash plus random base32 suffix; reuse per conversation instead of trusting model-supplied trace IDs. |
| T-18-04 | Repudiation | `diagnostics.ts` | mitigate | Preserve raw FlashQuery result and trace ID in details so Phase 19 can show auditable diagnostics. |
| T-18-05 | Information Disclosure | `diagnostics.ts` | mitigate | Normalize diagnostics without copying authorization headers, handoff bearer tokens, or MCP transport internals. |
| T-18-06 | Spoofing | `model-tool.ts` | mitigate | Do not fabricate progress, iteration counts, latencies, or completion metadata before the result envelope returns. |
| T-18-SC | Tampering | npm installs | accept | No package-manager installs are planned in this plan. |
</threat_model>
