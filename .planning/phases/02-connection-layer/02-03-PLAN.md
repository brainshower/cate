<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Manager status events -> future IPC layer | Events generated in main process will later be mapped to renderer broadcasts. |
| Subscriber registration -> manager internal state | Callers can register arbitrary event type strings and handlers. |
| Error text -> status subscribers | Network and HTTP error text can be observed by later UI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-T | Tampering | Event type routing | mitigate | Emit status transitions only through `emitStatus` and only to matching workspace `'status'` subscribers. |
| T-02-03-I | Information Disclosure | Status payloads | mitigate | Continue safe error handling; disconnected payloads include useful error text but no bearer token, connecting/live omit stale errors. |
| T-02-03-D | Denial of Service | Subscriber set mutation | mitigate | Preserve Set-based unsubscribe and avoid iterating unrelated workspace/event subscriber sets. |
| T-02-03-E | Elevation of Privilege | Renderer/preload/IPC surface | mitigate | Do not add `flashquery:*` IPC constants, preload APIs, renderer subscriptions, or BrowserWindow broadcasts in Phase 2. |
| T-02-03-R | Repudiation | Status transition traceability | accept | Phase 2 has unit-level event assertions; durable logging is not required and could risk secret-bearing logs. |
| T-02-SC | Tampering | npm installs | accept | No package-manager install tasks in this plan. |
</threat_model>
