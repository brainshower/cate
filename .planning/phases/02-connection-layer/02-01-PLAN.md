<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cate main process -> configured FlashQuery HTTP server | Untrusted network response from `/mcp/info` enters manager parsing and status state. |
| Stored workspace connection -> HTTP request construction | User-configured URL and optional bearer token influence outbound request shape. |
| Manager status event -> future IPC/UI consumers | Error text and metadata will later cross from main to renderer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-S | Spoofing | `/mcp/info` response identity | accept | Phase 2 only reports version/instance metadata from a configured endpoint; trust/auth policy for later MCP calls is outside this phase. |
| T-02-01-T | Tampering | Info JSON payload | mitigate | Validate `version` and `instance_id` as strings before emitting `live`; invalid/malformed payload becomes `disconnected`. |
| T-02-01-I | Information Disclosure | Probe request headers | mitigate | Do not send `Authorization` or bearer token data to `GET /mcp/info`; tests assert no auth header. |
| T-02-01-I2 | Information Disclosure | Status/error payloads | mitigate | Emit useful but safe error strings and never include raw connection auth token values in status events. |
| T-02-01-D | Denial of Service | Slow or failing info endpoint | accept | Retry throttling lands in Plan 02; this plan only classifies one explicit probe attempt. |
| T-02-01-E | Elevation of Privilege | Renderer/preload/IPC surface | mitigate | Do not add renderer, preload, IPC channel, or BrowserWindow broadcast surfaces in Phase 2 Plan 01. |
| T-02-SC | Tampering | npm installs | accept | No package-manager install tasks in this plan. |
</threat_model>
