# Plan 16.1: Vault Search Panel Registration And Search Core

<objective>
Register the Vault Search panel and implement its core search controls, grouped rendering states, explicit dispatch behavior, pagination, and search-specific disconnected/in-flight handling.
</objective>

<threat_model>
## Threat Model

- **High:** Running search automatically on filter changes can send unexpected semantic/vector queries. Mitigation: gate dispatch through button/Enter handlers only and assert filter changes do not call `flashquerySearch`.
- **High:** Stale results after disconnect can make old data look current. Mitigation: clear or mark current results on error/disconnect and track request IDs so late responses cannot overwrite current state.
- **Medium:** Renderer code could accidentally bypass main-process validation. Mitigation: call only `window.electronAPI.flashquerySearch` and keep request mapping limited to typed params.
- **Medium:** Adding a panel type can break drag/session/registry assumptions. Mitigation: update `PanelType`, `PANEL_DEFINITIONS`, `PANEL_REGISTRY`, app-store creation, and focused registry/store tests together.
</threat_model>
