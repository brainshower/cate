# Plan 15.1: Frontmatter Editor Opening And Placement

<objective>
Add the renderer/store path for opening independent FlashQuery frontmatter editor panels with correct URI shape, titles, and sibling placement semantics.
</objective>

<threat_model>
## Threat Model

- **High:** Creating frontmatter editors with body URIs can make body and frontmatter share model cache, dirty state, and save behavior. Mitigation: always derive frontmatter panels through `buildVaultUri(workspaceId, vaultPath, 'frontmatter')` and test that body/frontmatter file paths differ.
- **Medium:** Dock/canvas placement mistakes can orphan panels or open frontmatter far away from the document being edited. Mitigation: derive placement from the source body panel location and add store tests for dock and canvas cases.
- **Medium:** Adding tab actions can affect local-file or non-body FlashQuery tabs. Mitigation: gate affordances on `parseVaultUri(filePath)?.part === 'body'`.
</threat_model>
