# Plan 15.2: Editor Refresh And Frontmatter Editing Behavior

<objective>
Implement body refresh and independent frontmatter editing inside the existing Monaco editor panel without regressing local-file editing or existing FlashQuery body saves.
</objective>

<threat_model>
## Threat Model

- **High:** Refresh failure can corrupt unsaved user edits. Mitigation: never mutate model content or dirty state until the read succeeds and tests assert disconnected, not-found, and rejected-request preservation.
- **High:** Invalid YAML can write malformed data to FlashQuery. Mitigation: parse before IPC, block saves on parse errors, and test no IPC call occurs for invalid YAML.
- **Medium:** Managed frontmatter fields can be accidentally written back or, after filtering, become an empty payload error. Mitigation: filter `FLASHQUERY_MANAGED_FRONTMATTER_FIELDS` before write when unmanaged keys remain, preserve Phase 14's managed-only successful no-op behavior, and test both paths.
- **Medium:** Sharing state between body and frontmatter can clear the wrong dirty flag. Mitigation: key all model/dirty behavior by panel ID and full URI and add component tests for body/frontmatter independence.
</threat_model>
