<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer to preload/main | Renderer requests vault index through typed `window.electronAPI`; tokens and MCP clients remain outside renderer. |
| workspace A to workspace B | Workspace-scoped document names cross async cache boundaries and must not leak after switch/disconnect. |
| Pi extension events to renderer store | Tool result metadata can trigger cache refresh but must not carry credential fields into renderer state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Information Disclosure | renderer token boundary | mitigate | Use only `window.electronAPI.flashqueryListVaultIndex(workspaceId)`; never expose bearer tokens, handoff files, MCP clients, or auth headers to `agentStore.ts`. |
| T-20-02 | Information Disclosure | vault-index cache | mitigate | Store `vaultIndexWorkspaceId`, clear on disconnect/switch, and discard late responses whose request ID/workspace no longer matches current state. |
| T-20-03 | Tampering | extension tool event refresh trigger | mitigate | Refresh only from successful FlashQuery document mutation tool completions with `details.flashquery === true`; ignore failed/non-mutating/read-only events. |
| T-20-04 | Denial of Service | overlapping refreshes | mitigate | Last-fetch-wins request sequencing and loading-state stabilization prevent flicker loops and stale async churn. |
| T-20-SC | Tampering | npm installs | accept | No package installs are planned for this renderer/Electron phase; package legitimacy audit says none. |
</threat_model>
